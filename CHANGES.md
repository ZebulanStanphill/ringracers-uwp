# Changes from Ring Racers v2.4

Changes from vanilla [Ring Racers v2.4](https://github.com/KartKrewDev/RingRacers/releases/tag/v2.4). Engine changes are commits in [ZebulanStanphill/RingRacers](https://github.com/ZebulanStanphill/RingRacers), pinned as the `RingRacers` submodule; SDL changes live in `patches/sdl-angle.patch`, `patches/sdl-controller-duplicates.patch`, and `patches/sdl-egl-surface-handoff.patch`; `uwp/` and `build.ps1` provide the launcher and build.

Unless stated otherwise, changes apply only to UWP builds (`SRB2_CONFIG_UWP`, which defines `_UWP`). The GL2 RHI's general call reductions and OpenGL ES support, colormap caching, most Software optimizations, UDP error handling, Lua userdata set, state bookkeeping, and interpolation-list changes apply to every platform built from the fork. Individual Legacy GL entries identify other shared changes.

Game logic results are unchanged. Optimizations do the same work in less time, preserving replay, netplay, and ghost behavior. Status markers mean *(works on Xbox)* or *(untested on Xbox)*; qualifiers identify partial coverage. Confirmation refers to Xbox One X, including features confirmed before the driver replacement and carried forward unchanged. Build, CI, and tools have no Xbox marker.

## Platform and build

- **UWP library and launcher.** `SRB2_CONFIG_UWP` and the `ninja-x64_windows_uwp_vcpkg-release` preset build a static game library without a Git revision suffix in its executable name. The launcher starts it through `SDL_WinRTRunApp`, caches the CoreWindow on the UI thread, and reports the process memory budget; this builds on [worleydl's port](https://github.com/worleydl/ringracers-uwp), rebased onto v2.4.
- **Dependencies and CPU.** SDL2 and libuwp come from [worleydl/uwp-dep](https://github.com/worleydl/uwp-dep). The game targets Xbox One's Jaguar CPU with `-march=btver2`, also supported by Xbox Series X|S; Jaguar has no FMA, preserving the floating-point behavior of other x64 builds.
- **Direct3D 12 option.** The CMake option `SRB2_CONFIG_D3D12` builds VibeRant D3D (`src/hardware/r_d3d12`) and defines `HAVE_D3D12`, which guards every engine call into it; it is available only for UWP builds, where it defaults to on, and other builds leave the driver out.
- **Package.** The manifest version is 2.4.0.0 and requests file system, removable storage, network, expanded resources, and microphone access for voice chat. Runtime DLLs are not copied beside the static library.
- **Audio** *(works on Xbox)*. The audio driver is WASAPI instead of DirectSound.
- **Build script.** `build.ps1` builds the `RingRacers` submodule and SDL2 with this repository's SDL patches, verifies ANGLE's download with SHA-256, and generates the launcher solution.
- **CI.** This repository's CI builds the app; the fork's CI runs 36 native regression tests with ASan/UBSan, a `warp` job that compiles 97 translated add-on shader stages for Shader Model 5.1 and runs the Direct3D 12 WARP harness with the debug layer and GPU-based validation, and Linux and macOS builds without the Direct3D 12 driver. Each test was checked by mutating the production code it covers. Tests that ran identical code, duplicated a WARP pixel check or only parsed a debug command were removed. Negative controls assert their specific rejection in-process instead of passing on any failure; WARP keeps four shader and feature mutants as separate processes and checks every other oracle with a self-test and a registry of the scenes that ran. The WARP job caches its glslang and SPIRV-Cross build per runner image. [tests/README.md](https://github.com/ZebulanStanphill/RingRacers/blob/master/tests/README.md) describes coverage and limits.
- **Build artifacts.** The `build` job uploads a sideloadable `.msix` signed with a throwaway certificate, its certificate, and the linker map (`ringracers-uwp-symbols`). Actions use Node.js 24 releases, and Visual Studio's Developer PowerShell exports the x64 environment to later steps.
- **Shader smoke test.** The [installable PK3](https://github.com/ZebulanStanphill/RingRacers/blob/master/tests/addons/shader-smoke/README.md), which the fork's CI uploads as `shader-smoke-test`, supplies shader-only checker and water-ripple effects without gameplay scripts or replacement assets.
- **Renderer test map** *(works on Xbox)*. The [installable PK3](https://github.com/ZebulanStanphill/RingRacers/blob/master/tests/addons/renderer-test/README.md), which the fork's CI uploads as `renderer-test-map`, is a generated UDMF race map (`map RR_RENDERTEST`) with a room each for fog, overlapping water and heat haze, polyobject ripples, wall light slices, translucent ordering and brightmaps, a rainy hall whose sky shows a separate, brightly lit skybox room where rain must not be drawn (judged from a covered sky pit off the hall's east end, which has no rain of its own), and item boxes, revealed by a checkpoint just past the start line, that become a sprite-textured model when its `models/` folder is installed beside `ringconfig.cfg`. The add-on removes AI racers on this map, including bots added after loading, while keeping local split-screen players and leaving other maps and bot settings alone. Its scenery objects replace any game object that already uses their editor numbers when the map loads, logging which object it was. It carries an Encore remap that swaps red and blue, since without one Encore only mirrors the screen. Enable `cheats on` before using the map command. The water room has a long descent into a 608-unit-deep pool, a large flat bottom for submerged chase-camera views, and a far ramp back to the dry heat-haze ledge. `build.py` generates every texture, sprite and the map from code and runs ZDBSP, which CI builds from source to verify the committed PK3; it ships the sign's brightmap as a Doom patch and gives the orb's brightmap the orb's exact transparency, since vanilla Software can't read a PNG texture brightmap and walks a sprite's and its brightmap's columns together.

## VibeRant D3D renderer

### Direct3D 12 driver

- **Renderer and default** *(works on Xbox)*. VibeRant D3D draws upstream Legacy GL through `src/hardware/r_d3d12/` and is the default for new configs; valid saved renderer choices remain effective. Startup logs `UWP: VibeRant backend: D3D12`, and a failed driver start falls back to Software.
- **Shaders** *(works on Xbox)*. `fxc` compiles the built-in HLSL at build time for Shader Model 5.1 with an embedded root signature. Xbox One X exposes feature level 12_0 and Shader Model 5.1; Xbox One has no Shader Model 6.
- **Presentation** *(works on Xbox)*. Starting Legacy GL takes the window from ANGLE (with the first drawn frame instead if no ANGLE context exists yet, as with `-opengl`), and each frame is then copied into the driver's own three-buffer flip-model swap chain and shown at once, with `vid_wait` as the sync interval and a frame latency of 2. A screen whose aspect ratio differs from the window's is letterboxed. A CoreWindow takes one swap chain at a time, so `patches/sdl-egl-surface-handoff.patch` lets the driver destroy ANGLE's window surface, and recreate it when Software is chosen. If taking the window fails at startup, the game falls back to Software; a failure to take it with the first frame, resize the swap chain, or give the window back stops the game with an error. [Diagnostics notes](https://github.com/ZebulanStanphill/RingRacers/blob/master/docs/d3d12-diagnostics.md) describe the logs.
- **GPU synchronization** *(works on Xbox)*. The swap chain shares the driver's queue, so frames need no synchronization with ANGLE. The 2026-10-16 Xbox logs confirm the swap chain taking the window, giving it back for Software, taking it again, resizing, and letterboxing.
- **Resources and constants** *(works on Xbox, including 3D models and mipmaps)*. Drawing constants use a root-CBV ring, and fence completion controls resource and descriptor reuse, resizing, and shutdown. Models, indices, and sky buffers use persistently mapped 4 MB upload arenas; the driver generates RGBA8 mip chains on the CPU and skips redundant topology, stencil-reference, and viewport changes.
- **Texture heaps** *(works on Xbox)*. Textures use shared 16 MB heaps with 4 KB or 64 KB alignment, quarter-octave size classes, and a 4 KB guard after each reported allocation; textures exceeding the 4 MB class limit including the guard, or failing placement, get a dedicated heap with a spare 64 KB page. Committed textures remain a logged last resort: the guards protect against Xbox One's resource-state word corrupting neighboring or final texels, and the 2026-10-16 Xbox log shows dedicated heaps with zero committed textures; see [texture placement](https://github.com/ZebulanStanphill/RingRacers/blob/master/docs/d3d12-texture-placement.md).
- **Pipeline prewarming** *(works on Xbox)*. One worker prewarms 36 built-in shader pairings without blocking draws. `UWP D3D12: prewarmed` and the first 64 main-thread `PSO #` cache misses report creation cost.
- **Add-on shaders** *(works on Xbox)*. Pinned glslang and SPIRV-Cross translate `SHADERS` GLSL into Shader Model 5.1 HLSL for polygon, sky, and model layouts; `D3DCompile` compiles it, and load-time pipeline validation rejects invalid programs in favor of built-ins. Missing stages use shared built-in GLSL, Ignore custom shaders keeps built-ins, and custom sprite stages also cover clipped sprites; compiler notices ship in `Licenses`.
- **Custom water and shader limits** *(works on Xbox)*. Custom water color keeps built-in refraction through a composite variant; a custom vertex stage requires a whole-viewport capture, while capture/variant failure or Reduce VFX uses normal blending without refraction. Underwater/heat postprocessing stays built-in, arbitrary uniforms use their initializer or zero without engine setters, and uninitialized uniform arrays and extra vertex attributes remain unsupported; see [add-on shader notes](https://github.com/ZebulanStanphill/RingRacers/blob/master/docs/d3d12-custom-shaders.md).

### Matching Software

- **Palette rendering** *(works on Xbox)*. Ported from SRB2, palette rendering lights surfaces through colormaps, limits colors to the palette, and applies palette flashes and the color profile to the whole frame. It rebuilds cached textures when Encore's remap changes, preventing colors from the previous normal/Encore race from carrying over; without palette rendering, flashes remain white or pink overlays.
- **Brightmaps** *(works on Xbox, including Encore)*. Brightmapped pixels use the base colormap's full-bright row rather than a sector's tint/fade, in palette and smooth rendering, while retaining Encore's texel remap. SPRTINFO sprite brightmaps include roll rotation with the base patch's transform, pivot, flip, and origin; missing or differently sized maps fall back to ordinary lighting, and cache reloads/purges release rotated companions. Sprite brightmap selection and rotated companions apply to every platform.
- **Springs** *(works on Xbox)*. Springs use Software's origin and sprite-height sorting against solid walls, two-sided upper/lower walls, and opaque 3D floor sides and planes, including nearer faces drawn over them. Clipping removes rounding slivers and clamps crossed sprite light slices to prevent bow-ties, hiding Metropolis's springs inside bumpers without dashes; ordinary sprites and translucent or see-through sides retain per-pixel depth behavior. Flat silhouettes (all within a tenth of a pixel's angle of one plane through the camera), such as the seam between two sloped floors on one plane that Software leaves undrawn, no longer clip springs *(untested on Xbox)*; one beside the camera in Green Hills Zone had cut a whole row of springs out.
  - **Clipping bounds** *(works on Xbox)*. Capacity checks prevent spring and near-plane clipping from overrunning buffers; an oversized silhouette is ignored or its affected triangle remains whole, so a rare spring sliver can remain visible.
- **Water** *(works on Xbox, including split-screen and overlapping volumes)*. Translucent ripple surfaces refract the scene behind them. Unlike Software, which distorts only the background, this also refracts visible submerged geometry. It uses Software's wave timing, distance attenuation, and signed pixel rounding with viewport clamps and six blend modes. Coplanar pieces share an immutable, bounded capture expanded by disjoint strips and a 16-pixel ripple margin; intervening draws, different layers/slopes, or polyobjects start fresh captures, and the shared-platform `FOF_CUTEXTRA` rule removes hidden internal water/fog boundaries as Software does, retaining touching or different-kind boundaries.
  - **Water fallbacks** *(works on Xbox)*. Offscreen faces need no copy, near-plane crossings use conservative full-view bounds, and standalone polyobjects use bounded per-face captures. Reduce VFX disables distortion, opaque ripple surfaces keep texture-only ripples, and capture failure retains ordinary rendering; controlled Xbox performance comparisons remain pending.
- **Underwater and heat distortion** *(works on Xbox, including split-screen)*. Per-pixel sampling follows Software's wave shapes and tic timing rather than Legacy GL's coarse grid; underwater displacement reaches 1% of the full frame width, and sampling clamps to each viewport without affecting the HUD. Reduce VFX disables both effects, and desktop OpenGL retains its grid and single-view limit.
- **Fog** *(works on Xbox)*. With Shaders on, fog walls and planes remap the captured scene inside colored, inward, outward, and overlapping boundaries, using Software's integer light rows and control colormaps in palette mode or tint/fade equations in smooth mode. Each visible face copies its projected bounds into one retained RGBA texture, preserving portal/viewport clipping without depth writes; custom fog shaders own their output, and allocation failure uses the old shader.
  - **Fog approximation** *(works on Xbox)*. Shaders Off and desktop OpenGL retain one cached inward neutral camera-fog approximation: cap surface light, apply the colormap and sky attenuation once, and omit that block's boundary polygons. This shared-platform path needs no scene copies but can differ from Software in color, brightness, and boundary placement; colored, outward, and overlapping fog retain older paths.
  - **Overlapping fog order** *(works on Xbox)*. Every hardware renderer keeps fog planes at the same height in the order their fog blocks were created, so overlapping fog no longer switches color with the viewing angle; the first block wins, as in Software, though Software also draws the second block's plane in the first block's colors. Looking out from inside the overlap, the shared boundary wall also shows the first block's color, where Software shows the second's; hardware keeps the first, matching the fog you're standing in.
- **Palette fades and wipes** *(works on Xbox)*. Palette Rendering uses Software's fade-map rows before the HUD, clamps strength to the available rows, and leaves flashes/color correction to the final palette pass; missing resources or Palette Rendering Off use the overlay (`path=exact` or `path=overlay`). Transitions support black/white Mega Drive-style fades, inversion, Encore wiggle, and reversed fades, with the final current frame shown immediately; an unavailable full wipe falls back to two passes.
- **Encore inversion flag** *(works on Xbox)*. `PF_Invert` has a separate bit from depth writes so blend selection recognizes screen inversion instead of drawing a white quad.
- **Portals** *(works on Xbox, including split-screen)*. Special-40 linedefs show their paired destination through stencil openings and exit-plane clipping, using Software's tag pairing, rotation, and floor-height offset; the approach credits [SRB2Kart Saturn](https://github.com/Indev450/SRB2Kart-Saturn). `maxportals` defaults to 2, with 0 disabling portals; recursive views use the regular sky, maps without portals skip the search, and the player model can disappear near an opening as in Software.
- **Sky alignment and horizon boundaries** *(works on Xbox)*. Sky domes and the flat fallback honor single-patch header offsets, and empty two-sided sky boundaries no longer extend opaque floors over the background, fixing Water Palace's sky position and cutoff. The horizon check applies on every platform; real boundaries still extend, and signed sky offsets use multiplication instead of undefined negative left shifts.
- **Skybox visibility** *(precipitation works on Xbox; `RF_HIDEINSKYBOX` untested)*. Precipitation and things marked `RF_HIDEINSKYBOX` are excluded from skybox views on every platform. Upstream's Legacy GL draws rain in the skybox.
- **Black void** *(untested on Xbox)*. Screen areas the level doesn't cover, such as gaps with nothing behind them, views out of the map, or the camera clipped into a wall, are black, as in Software, instead of showing the sky that was drawn behind everything. The sky shows only through sky surfaces: sky-flat floors and ceilings (from either side, as in Software, including opaque 3D floors with the sky flat) and the existing sky walls, which write depth without color; one full-screen pass per view then blackens pixels that nothing drew, before sprites and translucent surfaces, which blend over black there. It applies inside skybox views, portals and split-screen views. The far clipping plane moves from 32768 to 131072 units so distant geometry isn't clipped into the void. Sky planes also claim their extension past horizon lines, as Software extends them, so the skies above Green Hills Zone's horizons aren't black. Translucent 3D floors with the sky flat and Boom fake-flat sky conditions don't claim sky. When the chase camera is pushed underground (below the floor in front of a raised step), the screen columns Software leaves empty there are black too *(untested on Xbox)*: Software treats a step whose top is above the screen as filling its columns, so VibeRant then clips the line like a closed door and draws black along it below the wall (or above an upper wall), meeting the wall's edge without overlapping it, instead of showing the level behind.

### Fixes to Legacy GL

- **Untextured steps** *(untested on Xbox)*. Where a floor steps up, or a ceiling steps down, and the wall between has no texture, the farther floor's (or ceiling's) flat continues across the step with that flat's lighting, as Software lets it bleed, instead of leaving a gap that shows what is behind. Neighboring sloped floors in Green Hills Zone meet a few thousandths of a unit apart, which showed as thin crack lines across the grass. It applies only while that flat faces the camera; sky flats and polyobjects are unchanged.
- **Walls cut by solid 3D floors** *(untested on Xbox)*. Software leaves the part of an upper, lower or one-sided wall inside a solid 3D floor's thickness undrawn and draws nothing behind it, so through a see-through 3D floor, such as Green Hills Zone's tube grates, that part is black (or the HOM flash). VibeRant D3D now fills it black too, instead of showing the level behind the wall, such as the sky or the grass outside the tube; the 3D floor and anything nearer still draw in front.
- **Lower-unpegged walls on slopes** *(untested on Xbox)*. A one-sided wall whose texture is lower unpegged now has the texture's bottom on its floor along the floor's slope, as in Software, on every platform; Legacy GL measured it from the sector's unsloped floor height, so Green Hills Zone's pit walls between the tubes showed the grass at the top of their texture at their foot instead of brick.
- **Wall light slices** *(works on Xbox, including split-screen)*. UWP clips each lighting band to its original wall and splits crossing slopes, preserving UVs, lighting, alpha, and solid-floor holes. This removes inverted slices that covered Water Palace scenery with brown wall pixels, without new GPU resources or copies.
- **Missing floors and ceilings** *(works on Xbox)*. BSP cuts send unsplit polygons to their actual side, and a closed GL-seg loop supplies a fallback for subsectors missing a polygon. This fixes reported holes on Green Hills Zone and Storm Rig on every platform; some inherited oversized subsector polygons remain possible.
- **Sprite-textured models** *(works on Xbox, including after video changes)*. Every platform prepares a model's selected sprite patch before reading hardware data and compares sprite dimensions when refitting UVs, preventing crashes with models such as item boxes after video changes.
- **Title background lighting** *(works on Xbox)*. Preparing neighboring 3D-floor lighting before use prevents a briefly lit title-map background during fade-in on every platform.
- **First frame after a map load** *(works on Xbox)*. View interpolation stays off after a reset until a frame of the new map is drawn, on every platform. A slow load used to run tics without drawing, so the first frame blended from the previous map's last view: after a race, EXIT GAME's fade-in showed only sky in hardware renderers and a wrong view in Software.
- **Fill transparency** *(works on Xbox)*. Every hardware renderer honors fill translucency and HUD fades, including the spectator Watching underline over the finish-grade icon. Opaque fullscreen fills retain the clear shortcut; translucent fills blend over the full surface.
- **Polyobject ripples** *(works on Xbox)*. Moving floors and ceilings use their control sector's ripple flag, including translucent planes, on every platform. Regular and polyobject planes honor Reduce VFX when selecting ripples.
- **Raw pictures** *(untested on Xbox)*. Every platform supports opaque intensity/grayscale and RGB24 pictures alongside palette, intensity/alpha, and RGBA modes, including nearest-neighbor resizing. Conversion validates headers, dimensions, modes, and lengths, ignores trailing bytes, and prevents RGBA destination overruns.

### Settings

- **Advanced menu** *(works on Xbox)*. The renderer list says **VibeRant D3D**. Options → Video → Advanced describes it as a Direct3D 12 port of Legacy GL with 3D models, true perspective and closer Software parity, and asks for visual bugs to be reported to GitHub.com/ZebulanStanphill/ringracers-uwp. Switching to it shows no confirmation or loading warning, and its **VibeRant D3D Options...** section has no blank rows.
- **Palette control** *(works on Xbox)*. `gr_paletterendering` defaults to On and requires Shaders on.
- **Better transparency ordering** *(untested on Xbox)*. Saved `gr_bettertransparency` defaults to Off on every hardware-renderer platform; On inserts blended sprites, models, linkdraw attachments, and always-on-top sprites into the transparent surface pass using overlap, depth, and plane-side checks. It adds per-view CPU sorting and storage without scene copies, preserves opaque depth drawing and water-capture runs, and works with Shaders on or off; proxy model bounds, unsplit face crossings, cyclic intersections, and triangles within translucent models limit accuracy.
- **Batching** *(works on Xbox)*. `gr_batching` defaults to On, resets at launch, and appears last in VibeRant D3D's options, as the one an average player needs least.
- **Texture Filter** *(untested on Xbox)*. VibeRant D3D's options show **Texture Filter** (`gr_filtermode`: Nearest, Bilinear, Trilinear, Linear_Nearest, Nearest_Linear, Nearest_Mipmap) where **Texture Quality** was; that setting only chooses Legacy GL's OpenGL texture format, while Direct3D 12 always uses 32-bit textures. A new mode applies at once, and **Anisotropic** takes effect with Bilinear, Trilinear, Nearest_Linear and Nearest_Mipmap, which filter distant texels.
- **Screen effects** *(works on Xbox)*. Options → Video → **Screen Effect**'s SalCRT and SalCRT Sharp apply in VibeRant D3D as a last pass over the frame, after Palette Rendering; screenshots and recordings stay plain. The game's own CRT shaders are read from its shader data and translated to Direct3D when first chosen; if that fails, the log says `screen effect ... failed:` with the reason and the frame is shown without the effect. Nearest and Sharp Bilinear only choose how Software scales its picture up, which VibeRant doesn't need.
- **Screen Scaling** *(works on Xbox)*. Options → Video → **Screen Scaling**, under Fullscreen, places the game's frame on the screen in every renderer: **Fit** (the default, as before) scales it to fit, keeping its aspect ratio; **Integer** scales it by the largest whole number that fits; **1:1** shows it unscaled. Both of those center it with black around it, and fall back to Fit when the frame is bigger than the screen. VibeRant D3D then sizes its swap chain to the screen and draws the frame into place after the screen effect; if it can't, the log says `couldn't place the frame` and Fit is used from then on.

## Software renderer and GL2 RHI

- **ANGLE/OpenGL ES 2** *(works on Xbox)*. ANGLE runs the RHI and presents Software's frames through its Direct3D 11 device (VibeRant D3D presents with its own swap chain), replacing worleydl's desktop OpenGL/Mesa path. The GL2 RHI supports ES 2 contexts, GLSL ES 1.00, core framebuffer entry points, `glClearDepthf`, unsized texture formats, RGBA screenshot readback, and no `glReadBuffer`; `patches/sdl-angle.patch` builds SDL with EGL/ES 2.
- **Display** *(works on Xbox)*. libuwp supplies display size and refresh rate, while rendering uses ANGLE's surface size, which may be smaller than the HDMI mode. The window stays fullscreen, fixing the tiny loading screen.
- **Encore distortion** *(works on Xbox, including split-screen)*. Encore mirroring combines with underwater and heat distortion instead of replacing them in Software and Legacy GL on every platform.

## Network

- **Unreachable UDP routes** *(untested on Xbox)*. Host-unreachable and network-unreachable sends, including Winsock 10065, count as dropped packets on every platform. Existing retries and timeouts decide recovery; other unexpected send errors remain fatal.
- **Online loading** *(works on Xbox)*. UWP VibeRant clients send basic keepalives during geometry/resource loading and vanilla tic acknowledgments at most once per clock tic while connected in-game, excluding demos and savegame redownloads. This prevents loading-related delay kicks without changing server delay rules or the receive limit; a kick logs the last reported delay/limit and local simulated, received, and level tics.
- **Track title timing** *(works on Xbox)*. Pre-race titles start with a fresh clock after loading and retain upstream animation steps and HUD timer clamps. Online VibeRant clients animate the title in the normal HUD while simulation catches up; hosts, Software, offline play, and demos retain the pre-level animation.

## Files and startup

- **Data and logs** *(works on Xbox)*. Assets use `E:\ringracers`; config and saves use `E:\ringracers\ringracers`, ignoring `-home` and `RINGRACERSWADDIR`. The save folder exists before the writability check. The log uses `E:\ringracers\latest-log.txt` because the package directory is read-only.
- **Missing game data** *(untested on Xbox)*. When `bios.pk3` isn't in `E:\ringracers`, the error asks first whether the USB drive with the `ringracers` folder is connected, says the folder must be at the top of the drive and hold the v2.4 assets, and points to the README, before the list of drives the app can see.
- **Game data in internal storage** *(untested on Xbox)*. The game files in `E:\ringracers\data` that are read when tracks and characters load (about 300 MB) are copied to the app's own folder on the console's internal storage, which Windows deletes when the app is uninstalled, and loaded from there. That storage is a volume of about 3 GB shared by the data of every sideloaded app, so music, alternative music and sound effects (about 430 MB) and staff ghosts (48 MB, read only for Time Attack staff ghosts) stay on the USB drive, and copies of them made by earlier builds, like any other file the game no longer keeps there, are deleted at startup. A launch that checks a file on the USB drive writes the copy as it reads the file, and keeps it only if the MD5 matches. Later launches load a copy without checking it again while its source keeps the size and last-write time it was copied from and the game expects the same MD5; otherwise the file loads from the USB drive and is checked and copied again. Staff ghosts are likewise checked once and then trusted while unchanged, from a small record of the check. Running out of space or failing to write stops copying for that launch without affecting the check; skipping the check with B stops copying too. The log lists where each file loads from and why (`UWP: data:`), anything deleted, the internal storage's free space (for this app and on the drive) and size, which volume the internal storage, the install and `E:\ringracers` are each on (serial number and NT path), and each file copied.
- **Sound effects in memory** *(untested on Xbox)*. `sounds.pk3` stays on the USB drive, so startup reads all of its sounds into memory at once (about 43 MB, in file order) instead of reading each from the drive the first time it plays, which could stall a race. Sounds are still decoded when first played, as before; sounds from other files, such as characters' voices and add-ons, load as before. The log reports how many sounds were read, their size and the time it took.
- **Background file check** *(untested on Xbox)*. Main files load with expected MD5s while a below-normal-priority worker verifies contents in 1 MB reads; zip local headers wait until an entry is used. B skips checking without a prompt, startup waits before network setup if needed, and mismatches raise the usual error at the next loading step or final wait; logs record per-file time/speed, outcome, and wait.
- **Music and sound hashes** *(untested on Xbox)*. Files without expected MD5s hash their names rather than contents for duplicate detection. They are not transferred to netgames or recorded in replays.
- **Direct3D 12 launch check** *(works on Xbox)*. Launch requires a hardware adapter that creates a feature-level-11_0 Direct3D 12 device and command queue, excluding software adapters and Basic Render Driver. Failure shows a Dev Home Game-type pop-up, flushes logs, and exits; the launcher links `d3d12.lib`/`dxgi.lib`.
- **Earlier loading text** *(untested on Xbox)*. Graphics, fonts, and console initialize before map thumbnails/minimaps; **Loading maps...** redraws up to ten times a second, keeping the file-check skip text visible.
- **Map cache** *(works on Xbox)*. Startup no longer inflates every map WAD (305 MB) and staff ghost (76 MB) to find each map's thumbnail and minimap and each ghost's time and name. `mapcache.bin` in the app's folder on internal storage keeps them between launches, keyed by each zip entry's path, CRC32 and sizes, so a new or changed game file or add-on is read as before and added. The first launch after an install or a data change builds the cache (about 17 MB). A save keeps only the entries in use, a file from another demo version or a damaged one is rebuilt, and a cache that can't be read or written is logged and skipped. Thumbnails still all load at startup, so menus are unchanged. A cache left in `E:\ringracers\ringracers` by earlier builds is deleted. The cache is read with one unbuffered read, and the log reports how long reading and saving it took and how many maps and ghosts came from it.
- **Header cache** *(untested on Xbox)*. Startup reads the first few bytes of thousands of textures and sprites to size them, each a separate seek and often a decompression; on Xbox that was about 8 s of a 13 s startup. Reads of up to 256 bytes from PK3 entries made during startup are kept in `lumpheaders.bin` in the app's folder on internal storage, keyed by each entry's path, CRC32 and sizes and the read's offset and size, and answered from it on later launches with the same bytes. Only entries used are kept; after startup every read goes to the files as before. The log reports hits, misses and how long reading and saving the cache took.
- **Lump lookups** *(startup works on Xbox; long names untested)*. On every platform, finding a lump by name in a file checks only the lumps whose stored name hash matches, from an index built when the file is added, instead of every lump in the file. Results are identical. On Xbox, these searches (mostly for HUD graphics) took about 4.5 s of a 26 s startup. Lookups by long name use the same index; sprite brightmaps look one up for every visible sprite every frame, which scanned every lump of every file for names that don't exist (0.8% of race time).
- **Folder lookups** *(untested on Xbox)*. On every platform, finding where a folder starts in a PK3 uses an index of the folder paths in each file, built when the file is added, instead of comparing every entry's path. Results are identical. On Xbox, looking up each map's staff ghost folder in every file took about 4 s of startup.
- **Texture lookups** *(untested on Xbox)*. On every platform, finding a texture by name uses an index of the loaded textures and a hashed cache of earlier answers instead of scanning both. Results are identical, including newer textures taking precedence over older ones with the same name. On Xbox, the brightmap definitions' lookups took about 5.5 s of startup.
- **Loading-to-intro transition** *(works on Xbox)*. The intro starts with the credits card instead of six blue tics, without changing timing. VibeRant D3D skips clear-only presentation before its first drawn frame, keeping the loading screen visible instead of flashing black.
- **Skipping the intro** *(untested on Xbox)*. A press skips an intro logo as soon as it's on screen, instead of being ignored for the first half second of each scene; the opening credits card, which couldn't be skipped at all, now skips to the disclaimer. The disclaimer still has to slide in and finish fading in its text before it can be dismissed. Controllers already connected at startup are opened while the game loads, rather than once the intro's first frames have been drawn.

## Performance

### Rendering

- **Level precaching** *(works on Xbox)*. Legacy GL warms walls, flats, brightmaps, FOF control sectors, existing models, and current player models/colors during loading, then repeats player warming after spawning and hooks. Dedicated servers, reloads, snapshots, and rewind skip it; sprite-textured models, future animation frames, later objects, and view-dependent remaps remain lazy, and Models must be enabled for model warming.
- **Rolled sprites** *(untested on Xbox)*. VibeRant D3D draws sprites tilted by roll (karts on slopes, spinning objects) from the unrotated sprite texture, with the pixel shader applying Software's exact integer rotation, instead of rotating each new angle on the CPU and uploading it as a new texture. Races on Xbox created 20-60 such textures a second (about 1.8% of 3D time rotating and 3% of race CPU creating them, plus hitches). Sizes, offsets and cropping still come from the CPU, cached per frame and angle, so sorting and clipping are unchanged; brightmaps use the same mapping. Floor and paper sprites, linked sprites, custom sprite shaders, Shaders off, filtering other than nearest, mipmaps and very large art keep CPU rotation. The perf log reports how many rolled sprites each path drew.
- **Batch sorting** *(untested on Xbox)*. On every platform, Legacy GL batches sort an index array by compact keys copied out once per frame, instead of comparing large polygon entries and their texture pointers on every comparison, which cost about 7% of 3D drawing time on Xbox. Sorting the keys themselves was tried first and doubled the sort time, since qsort moves whole elements. Ties fall back to submission order, so the order is total; polygons with different colors may draw in a different order than before, where the old comparison was inconsistent.
- **Drop shadows** *(untested on Xbox)*. On every platform, Legacy GL finds the `DSHADOW` lump once, and again only after a file is added, instead of searching for it by name for every shadow every frame.
- **Rotated flats** *(untested on Xbox)*. On every platform, Legacy GL computes a rotated floor or ceiling texture's cosine and sine once per plane instead of four times per vertex, with identical results.
- **3D floor light lists** *(untested on Xbox)*. UWP keeps a sector's 3D floor light list when its allocation is big enough instead of freeing and reallocating it, which happened every time a sector with moving 3D floors was prepared, because a list that came out shorter than counted never matched the count again. The contents are identical.
- **Device-removal checks** *(untested on Xbox)*. Upload rings read a removal flag set by failed calls or fences instead of making a kernel query on every allocation. A full device check still runs once per frame.
- **Video memory safeguard** *(untested on Xbox)*. Exceeding the local budget schedules a texture-cache flush for the next frame, at most once every five seconds. Model buffers remain, but reloading textures can hitch.
- **GL2 call reduction** *(works on Xbox)*. Every platform skips redundant state/texture/buffer binds, disables only enabled vertex arrays, caches uniform locations, changes sampler uniforms only when needed, and retains framebuffers. Colormap/lighttable textures upload only after changes and expire after 300 unused frames; palettes upload only when changed and the default colormap once, while UWP uses `GL_RED` with `EXT_texture_rg` where available to avoid ANGLE's luminance conversion.

### Software renderer

- **Planes and sorting** *(works on Xbox)*. Every platform clears only visible visplane columns, skips draw nodes outside a sprite's columns before reading them, and computes 3D-floor plane bounds once during sorting.
- **Columns** *(works on Xbox)*. Every platform leaves unused thick-side slots alone, copies wall-column data only for remapping, computes masked clipping limits once, and passes read-only column data directly to drawers. UWP also inlines `R_GetTextureNum`.
- **Screen tilting** *(works on Xbox)*. Every platform steps along source rows instead of rebuilding a full-screen pixel map, preserving float stepping, clipping, zoom, and mirrored sampling. Large views share work across Software workers.

### Game logic

- **Arithmetic and references** *(works on Xbox)*. UWP inlines `FixedMul`, release-build `P_SetTarget`, and `P_MobjWasRemoved`, preserving collision callback reference order and `PARANOIA` checks.
- **Subsector cache** *(works on Xbox; the larger cache is untested)*. UWP caches `R_PointInSubsector` results for 4096 recent points (2048 sets of two; 512 before, which answered only about 60% of lookups in races) and clears them when the BSP loads or is freed.
- **Lua userdata** *(works on Xbox)*. Every platform tracks pointers with Lua userdata, letting frees skip Lua when none exists.
- **State bookkeeping** *(works on Xbox)*. Every platform gives each `P_SetMobjState`/`P_SetPlayerMobjState` nesting depth its own table and clears only recorded states. Calls that remove an mobj balance the nesting count instead of making later calls look nested.
- **Interpolation list** *(works on Xbox)*. Every platform records each mobj's interpolation-list slot so removal needs no search.

### Frame pacing and threads

- **Pacing** *(works on Xbox)*. Frames skipped to catch up on simulation do not sleep; drawn frames still sleep to the cap with V-Sync and a matching-refresh cap, following worleydl's Xbox timing fix.
- **Thread pool** *(works on Xbox)*. The pool uses Xbox's allocated processor count, falling back to upstream's hardware count when no processors are marked.

## Diagnostics

- **Startup and performance logs** *(works on Xbox)*. Startup records graphics/device capabilities, surface size, shader compilation, first-frame steps, loading/asset times and logging cost, memory budgets, CPU sets, and thread-pool size. Every five seconds `UWP perf:` reports FPS, frame/tic and HUD/present times, draws/uploads/resources, mobj/collision/Lua activity, subsector-cache hits, main-thread CPUs, profiler pauses, and renderer/portal CPU and GPU costs.
- **Driver counters** *(works on Xbox)*. `UWP perf:   D3D12:` includes `per frame` constant updates (`root CBV ring`), `pipeline:`, `rings:`, `textures:`, `models`, `texture heaps:`, `palette:`, `screens:`, `water:`, `portals:`, and `present:` statistics. These identify pipeline creation, upload peaks/wraps/stalls, storage, lazy models/mips, screen/fog/water copies, and synchronization, including the swap chain's copy, latency-wait, `Present` and failure counts.
- **ANGLE cost** *(works on Xbox)*. With the Software renderer, `UWP perf:   ANGLE GPU:` adds per-frame GPU time (timestamp queries on ANGLE's Direct3D 11 device) for the screen upload, 2D/upscale/ImGui and total, with worst frame, idle until the next frame, and timed/not-ready/disjoint counts. Idle is not cost: the GPU reaches the end of the present only with the next frame's commands, so it's excluded from total. A stage the CPU feeds slowly reads as an upper bound. The profiler splits level samples by renderer (`Software: 3D view`, `Legacy GL: 3D view`), and `tools/profile-report.py` shows each phase's and renderer's share inside ANGLE (`libGLESv2.dll`/`libEGL.dll`); `perf-summary.py` averages the new line. On Xbox One X at 1920x1080, a Software race spends about 1.4 ms of GPU and 8% of its main-thread time in ANGLE, so a Direct3D 12 RHI for Software is deferred.
- **Spring probe** *(works on Xbox)*. `gr_springprobe` waits for the console to close, then logs one main-world view, excluding skybox/portal passes. `UWP spring probe camera:`, `UWP spring probe:`, `UWP spring entry:`, `UWP spring result:`, and `UWP spring probe end:` record camera/settings, sprite heights/quad/depth, wall/plane tests and cuts, remaining area, and piece limits without changing drawing.
- **Pixel history** *(untested on Xbox)*. `gr_surfaceprobe [x_percent y_percent]` defaults to `15 35` from the top-left and requires a level, hardware rendering, split-screen off, and Batching off; it captures after the console closes. `surface probe:` logs `begin`, changed-color `sample=` rows with source/texture/flags/shader/depth/alpha and up to eight vertices, and `end`; one 4 MB readback buffer holds up to 8,192 samples with 256 color-change reports and explicit overflow/omission counts, is released after the frame, and does no work while inactive. The requested frame stalls for readback and is unsuitable for benchmarking; see [Direct3D 12 diagnostics](https://github.com/ZebulanStanphill/RingRacers/blob/master/docs/d3d12-diagnostics.md) for row formats and timeout logs.
- **Frame, title, and fade traces** *(works on Xbox)*. `UWP frame:` records positions, camera, elapsed time, tics, interpolation, title timers, and copied/shown slot IDs (the swap chain's back buffer) during titles and level seconds 10–20, capped at 300 frames per window. `UWP: track title:` summarizes animation timing; `UWP fade:` records state/load/wipe/palette changes in ten-second, 200-event windows and caps title-map/light-fade samples at 20 each.
- **Memory and stalls** *(works on Xbox)*. Perf summaries include DXGI local budget/usage and tracked texture, buffer, ring, render-target, and swap chain storage. `GPU frame exceeded 250 ms` logs once, while abandoned fence waits log at most once per second with suppressed warnings counted.
- **GPU failure details** *(untested on Xbox)*. Device removal and the first GPU-wait timeout dump DRED breadcrumbs when available, with page-fault details on removal. Search for `GPU wait for <what> timed out after N ms; breadcrumbs:` and `DRED:`.
- **Profiler and crashes** *(works on Xbox)*. `src/sdl/i_uwpprofile.cpp` samples the main thread about 50 times a second from the start of startup, writing stacks/activity to `E:\ringracers\uwp-profile.txt`. Play is split into phases by activity; startup, menus and the title screen, a paused or loading level, intermission, voting, the podium and cutscenes each form a phase of their own, which `tools/profile-report.py` reports separately from play. A vectored exception handler logs crashes and stacks because the app runtime bypasses the game's signal handler; it cannot catch stack-cookie termination.
- **Error dialog** *(works on Xbox)*. The short Xbox dialog contains the error plus visible drives and their `ringracers` folders, and saves the text to `E:\ringracers\error.txt`.
- **Tools.** `tools/` summarizes perf logs, resolves profile/crash addresses to functions, and annotates instructions with samples.

## Other fixes

- **Options button slide** *(works on Xbox)*. Submenu title buttons start their slide once and finish at or after the final tic, preventing repeated bouncing when low frame rates skip a menu tic.
- **Console slide** *(works on Xbox)*. On every platform, opening and closing use elapsed time since the last movement, keeping the intended speed through skipped frames and stalls.
- **Duplicate controllers** *(works on Xbox)*. `patches/sdl-controller-duplicates.patch` stops each controller from appearing twice, and each press from counting twice, in Game mode.

## Removed or disabled

- **Old hardware driver** *(untested on Xbox)*. The Direct3D 11 driver, Shader Model 4 built-ins/tests, and `gr_d3d12` Off/Once/On selector are removed; an old config line reports `Unknown command` once. A saved `renderer VibeRant D3D11` is rejected as an invalid value and keeps the VibeRant D3D default. The old sharing/shader probes no longer run, and VibeRant D3D replaces `r_opengl.c` only in builds with `SRB2_CONFIG_D3D12` (UWP by default).
- **App-incompatible crash handlers.** DbgHelp minidumps, cpptrace, and `exchndl` are disabled for UWP; [Diagnostics](#diagnostics) describes their replacement.
- **Master server debug output.** Verbose `masterserver_debug` curl output and the Windows log-copy helper compile only with `LOGMESSAGES`, which defaults to on.
